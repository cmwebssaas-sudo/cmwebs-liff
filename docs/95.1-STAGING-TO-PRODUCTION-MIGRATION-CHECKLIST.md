# Phase 95.1 — Staging to Production Migration Checklist

This checklist is a manual release gate. It does not authorize deployment.

## A. Immutable baseline and rollback

- [ ] Record Production branch, commit and clean status.
- [ ] Export current Production Apps Script source and SHA-256 manifest.
- [ ] Record existing Web App deployment ID and immutable version.
- [ ] Export installable trigger handler/schedule/owner/timezone inventory.
- [ ] Record a recoverable Production Spreadsheet backup reference.
- [ ] Export Script Property **key names only**; never export values to Git.
- [ ] Prepare an isolated clasp release tree bound to the confirmed Production project.
- [ ] Verify rollback restores source HEAD, Web App version and trigger inventory—not only deployment version.

## B. Reviewed release boundary

- [ ] Include `V2_LINE_IDENTITY_SECURITY.js`.
- [ ] Include `V2_RBAC.js`.
- [ ] Include `V2_SETTLEMENT_TRANSACTION.js`.
- [ ] Include reviewed Phase 90–94 runtime modules only.
- [ ] Exclude staging registration/setup modules and disposable fixtures.
- [ ] Exclude tests, repair/admin tools, local credentials and `.clasp.json` from Git.
- [ ] Review every common Production/staging module diff individually.
- [ ] Generate and approve the exact SHA-256 push manifest.
- [ ] Confirm route count and handler coverage expected by the release.

## C. Production configuration (features initially disabled)

- [ ] Set `CMWEBS_ENVIRONMENT=production`.
- [ ] Set `CMWEBS_LINE_LOGIN_CHANNEL_ID` to the verified Production LINE Login channel.
- [ ] Confirm the Production LIFF has `openid` scope.
- [ ] Confirm Production frontend uses POST bridge and sends `liff.getIDToken()`.
- [ ] Keep `CMWEBS_FEATURE_ALLOW_TEST_IDENTITY=false`.
- [ ] Keep all new lifecycle feature flags disabled before migration.
- [ ] Confirm LINE Messaging token, Spreadsheet ID and URLs remain existing Production values.

## D. Schema migration window

- [ ] Place Production in an approved maintenance window.
- [ ] Temporarily enable `CMWEBS_FEATURE_SCHEMA_MIGRATIONS=true`.
- [ ] Run reviewed migrations once in dependency order:
  1. Notification Queue/log schema
  2. Repair workflow
  3. Contract lifecycle
  4. Billing/payment lifecycle
  5. Move-out/deposit settlement and settlement ledger
- [ ] Verify header names/counts and existing row preservation read-only.
- [ ] Disable `CMWEBS_FEATURE_SCHEMA_MIGRATIONS` immediately.
- [ ] Confirm no disposable or test row was created.

## E. Trigger gate

- [ ] Install/reconcile exactly one notification queue worker trigger.
- [ ] Install/reconcile exactly one contract-expiry trigger.
- [ ] Install/reconcile exactly one billing lifecycle trigger.
- [ ] Confirm owner, timezone and schedule.
- [ ] Confirm no trigger targets staging/test/repair functions.
- [ ] Verify stale `processing` notification recovery before enabling Production queue traffic.

## F. RBAC and authentication validation

- [ ] Invalid/expired/wrong-audience ID token returns a structured auth failure.
- [ ] Caller-provided UID cannot alter resolved identity.
- [ ] GET write attempt returns `AUTH_POST_REQUIRED`.
- [ ] Tenant A cannot access Tenant B.
- [ ] Viewer cannot write.
- [ ] Maintenance can update repair but cannot mutate contracts/payments.
- [ ] Accountant can approve payment but cannot manage team/contract unless explicitly granted.
- [ ] Manager contract/payment permissions match configured membership flags.
- [ ] Admin/owner flows pass.
- [ ] Cross-Workspace attempts fail closed.

## G. Feature enablement order

- [ ] Enable and verify `NOTIFICATION_QUEUE`.
- [ ] Enable and verify `REPAIR_WORKFLOW`.
- [ ] Enable and verify `LEASE_LIFECYCLE`.
- [ ] Enable and verify `BILLING_LIFECYCLE`.
- [ ] Enable and verify `MOVE_OUT_SETTLEMENT` last.
- [ ] Stop immediately if any stage fails; do not enable downstream features.

## H. Settlement transaction validation

- [ ] Submit a disposable staging-equivalent settlement with a unique idempotency key.
- [ ] Replay the same key and confirm no duplicate mutation.
- [ ] Inject a controlled failure and confirm ledger `rolled_back` plus restored rows.
- [ ] Confirm a positive refund requires reference evidence.
- [ ] Confirm payment and termination permissions are both required.
- [ ] Confirm no real refund is initiated by the test.

## I. Deployment and smoke test

- [ ] `npm run validate` PASS.
- [ ] Production release-tree validator PASS.
- [ ] Full staging suite PASS, including hosting artifact integrity.
- [ ] `git diff --check` PASS.
- [ ] Push only the approved SHA manifest.
- [ ] Create a new immutable Apps Script version.
- [ ] Update the existing Web App deployment; preserve URL.
- [ ] Smoke test authenticated tenant and authorized landlord reads first.
- [ ] Execute only approved disposable write cases.
- [ ] Verify queue/log correlation and absence of sensitive log values.

## J. Rollback criteria

Rollback immediately for identity mismatch, cross-Workspace access, permission
bypass, duplicate financial mutation, rollback failure, stuck notification
worker, schema mismatch, or elevated error rate.

Rollback order:

1. Disable Phase 90–94 feature flags.
2. Disable/reconcile new triggers.
3. Restore approved Apps Script source SHA and push manifest.
4. Point the existing Web App deployment to the recorded immutable version.
5. Restore Spreadsheet only when data reconciliation proves it is required.
6. Run read-only identity, Workspace, queue and ledger verification.

Production promotion remains blocked until every mandatory checkbox has named
evidence and an accountable human approver.
