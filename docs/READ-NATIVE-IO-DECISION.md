## 要解決的卡點

已批准的 [憑證用途修訂](READ-CREDENTIAL-READBACK-DECISION.md) 保留固定96、
四窗口G32、P4、T3，加歷史25，總額160，且各桶不得互借。P4已各有唯一用途；
F的每個alias只給一次讀回。實際UI的綁頁／導覽與後續AX讀取是不同操作，
不能把它們藏在一次`externalRead`中。原生producer只讀已綁定tab，
目前五個F原生設定／觸發器／OAuth觀測與完整窗口仍未接線。

另一個限制是完整接線完成前，新Google操作維持STOP。這使尚無可用原生
快照的觀測器無法先核對實際頁面格式與操作路徑。本文件只解除這個唯讀
前置循環，不以本地fixture、較早快照或預期常數代替實際驗收。

這不是已證明今天的頁數超額，也不宣稱修改後一定可執行；它讓實際唯讀
預查有明確用途，之後才能判定整條流程能否在160內完成。

## 提案：只讓 N 與 G 共用原本的 32 次

| 部分 | 保留／修訂 | 上限 |
| --- | --- | ---: |
| 歷史 | 原counter、receipt、epoch及已花次數保留，不退款、不重設 | 25 |
| A–I固定操作 | 原96個用途、各次數及順序保留；F前後各15項不減 | 96 |
| P | caller-bind、publisher-bind、既有publisher-refresh、publisher-userinfo，各一次 | 4 |
| T | 只查原已發出RPC的未知終態；不重送RPC | 3 |
| N＋G | 下列固定目的地唯讀導覽／預查＋四個完整原生窗口，共用原G32 | 32 |
| 合計 | 累積硬上限 | **160** |

N不是額外32次。N每花一次，就少一次可供G使用。所有失敗、被拒及UNKNOWN
照扣，不能把換頁、綁tab、初始化AX或設定後讀回當免費操作。

N只允許既有核准合成專案的：原script設定、原script觸發器、薄script設定、
OAuth Testing audience、該試驗OAuth client表單／讀回，以及原生執行清單
的必要導覽／顯示控制。固定實體ID／actor與觀測目的先pin；不得提供任意
URL、做瀏覽器清單／帳號搜尋、讀正式表、擴大Source Viewer或新增Scope。
同一動作若實際會寫遠端設定／建立資源，仍走原A–I唯一用途，不能改標N。

四個G窗口仍各自必須有當次同token身分、完整來源／窗口及配額證據；
每窗清單快照仍最多4頁。原每窗最多8次及setupReads最多2次，改由共享32
及剩餘必要查核預留約束。已批准的四次G身分GET與每窗配額查核不得省略、
重放或被N挪用。只有未使用的導航／分頁空間可被其他必要唯讀操作使用。
未知時不能將最低12次G當成已證明足夠的完整觀測成本。

## 唯讀預查、准入與停止條件

1. 修改後的原canonical控制器、purpose allowlist、共用計數、排他鎖、
   UNKNOWN／stop／copied recovery測試及審查先通過；才可建立原counter的
   claim並預扣。不得另外建立counter或零歷史epoch。
2. 完整原生observer尚未完成前，允許先完成原P的caller-bind與publisher-bind，
   各扣原唯一格，依原固定reference／actor規則核對；不另做清單或免費綁頁。
   僅這兩次P綁頁屬本次提前例外；原publisher-refresh／publisher-userinfo
   仍等完整接線完成後，依原批准用途各做一次，且先於A–E或handoff。
   不提前續期，避免離線補接線期間消耗唯一publisher token的餘命。
   隨後最多8次N操作作原生介面預查。這8次包含在N＋G32內。
   只看上述固定頁面，不建立資源、輸入新憑證、
   授Reader、改Properties、發布、切開關或呼叫試驗RPC。P四個目的與順序
   仍保留，不能拿P做額外預查；既有grant續期也只能走已批准P用途。
3. 預查記錄只用來實作／核對實際UI觀測器，不能當後續新鮮度或quota proof。
   必須列出剩餘A–I、P、四窗口、T及回退的具體實際IO地圖與上限。
   無法在剩餘額度完成，立即停止此方法，不繼續增加工具或要求320。
4. **研究准入**只允許上述P兩次綁頁與最多8次N。每次先預扣並保留所有
   尚未完成的固定操作、P餘額、T3及四窗口不可省略的身分／配額／最低頁面
   額度。最低12次G只是不可挪用的底線，不是完整觀測成本；此時完整成本
   可以是UNKNOWN，但不得因此核准任何遠端變更、續期、新grant或RPC。
   **後續變更／RPC准入**則必須已有完整實際IO地圖與成本上限，不能用
   最少一頁推算足夠。送RPC前另須完成原全部安全與回退接線、測試／
   審查及前15項實際查核，並為後15項及完整後窗口保留已列明的額度。
5. 原C兩次editor還原及I17獨立cleanup不得被N／G／其他普通操作消耗；
   T3及唯一H1也不借用。每分鐘10次、single in-flight、六分鐘runtime／
   token餘命、15秒簽章、900秒／台北日均保留。
6. 任一窗口不完整、需第五頁、缺執行身分／終態、quota不可證明或總額不足，
   就STOP。已發出結果不明仍pending，不重送RPC；保留原T3及I17回退。
   無法證明遠端終止／撤權，不宣稱成功。本人登入、新credential輸入、
   當次安全存取確認仍由本人於真正的動作點處理。
7. P綁頁、N預查、離線補接線與後續恢復，都限於原claim的同一台北日與
   原expiresAt窗口（最多六小時）。不得延長deadline、換claim／epoch、
   重綁已用P、重做已花的預查或再續期來恢復。原pinned控制器／copied
   recovery快照也不換綁；若需更動它們、跨日、過期或失去原holder，就
   停止本次普通IO並保留所有歷史及UNKNOWN。只有原獨立cleanup仍可依
   其既有能力處理；沒有遠端變更也如實記錄，不宣稱完成未執行的回退。
   本修訂不提供過期後自動重開試驗的授權。

## 沒有改變的驗收與風險

只有一次wrapper→library compatibility，不增加其他試驗入口。Private-library
相容性仍UNKNOWN；不得為成功而補Source Viewer。原始source／serving保留、
Google白名單競態隱私、撤權、新鮮度、每日900秒、500房、實際效能及真機
門檻不變。已批准的24小時並行觀察／逐頁上線與上線後七日觀察不變，
T0仍NOT_STARTED，所有正式開關off。沒有新增費用或正式資料存取。

風險：共用額度可能更早用完；未通過准入就停止，沒有完成保證。新增目的
必須受固定實體與階段約束，不能形成通用瀏覽器或任意IO通道。
用途修訂不替代任何真實驗收，也不授權在接線未完成時先送RPC。

若不採用，本次已批准用途與原25／160原封保留，新Google操作繼續STOP；
已完成的本地程式／CI及原GAS回退保留。若採用後停止，保留原claim／花費／
UNKNOWN，依原獨立還原／cleanup處理，不重置或補跑來救回成功。
