## Root cause

`htmlBridgeOutput_()` returned an Apps Script HtmlService page whose user HTML
runs inside a nested Google sandbox iframe. `window.parent.postMessage()` sent
the response only to the Apps Script wrapper, not to the top-level LIFF page.
The frontend also rejected messages whose source was not the outer form iframe,
which cannot match the nested sandbox window. Both tenant and landlord requests
therefore ended with `API_TIMEOUT` even though the backend returned HTTP 200.

## Transport change

### Backend

- `htmlBridgeOutput_()` now sends through `window.top.postMessage()`.
- Target origins come from `CMWEB_TENANT_FRONTEND_BASE_URL` and
  `CMWEB_LANDLORD_FRONTEND_BASE_URL` through the existing runtime environment
  helpers.
- Duplicate origins are removed.
- Wildcard target origin is not used.

### Frontend

- The bridge accepts messages only from HTTPS `script.google.com` or an Apps
  Script `*-script.googleusercontent.com` sandbox origin.
- The fixed envelope source and per-request random request ID remain required.
- Client-provided LINE UID is still prohibited.
- LIFF ID token is still sent only through POST for server-side verification.
