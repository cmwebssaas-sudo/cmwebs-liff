# 第一階段相容性試驗精簡草案

建議模型／速度：GPT-6.1 Sol／高。狀態：**待房東明確同意；尚未改控制器、額度或執行 Google 操作。**
本草案與 [24 小時加速上線修訂](READ-ACCELERATED-ROLLOUT.md) 是兩個不同決定，
可一次確認；同意縮短觀察期不會自動同意減少第一階段 RPC，反之亦然。

## 要排除的阻礙

目前第一階段有 wrapper 與 qualified 兩次 compatibility，各自完整前後查核。
固定操作127，加歷史25，僅剩8次；八個原生窗口就已用完，無導航或分頁空間。
160 是已批准的累積試驗上限；320 已拒絕。不能重新 seed、退款、換 epoch、
借回退預留或把原生介面操作改成免費。

現有 generator 的 wrapper authorizeTrial 會委派 AuthorityTrial.authorizeTrial。
因此可以先只驗證這條 wrapper → library 的完整鏈；停止把另外一次直接
qualified API 呼叫列為第一階段必做。這僅減少第一個可行性探查的入口數，
不表示 Google 已允許這個身分／library 組合，也不表示投影、撤權或效能通過。
來源：[C3 固定 generator](https://github.com/cmwebssaas-sudo/cmwebs-liff/blob/71cc63687ba73385562de822b6907930024243fd/scripts/build-read-authority-trial-entry.mjs)。

## 唯一執行入口與保留條件

- 第一階段只允許一次 wrapper compatibility RPC，不重送、不另跑 qualified，
  不發 authority／oracle。wrapper 失敗就停止此路徑，不用第二入口嘗試救回成功。
- 仍只使用新無原指令碼綁定的合成表、原指定 caller、原三個 caller Scopes、
  無原表／library source Viewer、原15秒簽章及每分鐘10次上限。
- 該次 RPC 前後各保留原15項完整 release observation，不刪任何一項。
  caller／publisher 前後完整原生窗口由八個減為四個，仍要求完整窗口、來源、
  身分、配額及新鮮度；一頁、部分 duration、HTTP成功或本地 fixture 不能代替。
- 單一 in-flight、原鎖、durable debit、六分鐘 runtime/token 餘命與900秒／
  台北日保留。無法確認原生用量或原已發出執行狀態就保留 UNKNOWN，不重送。
- 完整C3權限、Google白名單／欄位競態隱私、資料新鮮度、效能與C1同步等
  後續 gate 仍需完成；一次 compatibility 不能用於正式開關或正式表存取。

## 維持160的逐桶硬上限

| 部分 | 內容 | 次數 |
| --- | --- | ---: |
| 已花 | 原counter全部歷史，保留25 | 25 |
| A／B／C／D／E | 原準備／合成表／發布與還原／薄入口／OAuth，9＋13＋9＋10＋7 | 48 |
| F | 單次RPC前後各15項完整查核 | 30 |
| H | 一次wrapper compatibility | 1 |
| I | 原獨立17項cleanup；不借給查核或探查 | 17 |
| G | 四個窗口各最多8次；每窗最多4頁、2次介面控制／設定讀回、1次身分、1次配額讀回 | 32 |
| P | 原生準備最多4次，兩個帳號各最多2次綁頁／準備讀回 | 4 |
| T | 原已發出執行的未知終態唯讀查核最多3次 | 3 |
| 合計 | 每個桶／子桶不可互借，不自動增加RPC | **160** |

A至I固定操作共96；加已花25為121，剩39全數分配G32／P4／T3。
C的原editor還原2次已在C9內，另保留其用途，不重複加計或借出。
固定A–I原方法中的所有原生管理／設定讀回也照原表計數，不能轉到免費項目。
G的身分及配額子桶是獨立預留，不因同一頁可能包含欄位而拿去讀額外列表頁。

這是**有界方法提案，不是當前頁數、實際成本或可執行性的證明**。歷史publisher
前兩頁400筆仍有下一頁，至少三頁；不能據此推測今天不超過四頁。
任一窗口有第五頁、需要第三次控制、第三次帳號準備，或未能取得適當配額
證據，就停止。T耗盡仍未知就保留pending並走I17撤權，不宣稱遠端已終止。
失敗操作照扣、不退款；不得再建一套無界本地工具來掩蓋上限不符。

## 採用步驟與判定

1. 房東明確同意本次「第一階段只跑一次wrapper」及上述160內的分配。
2. 修改既有純本地budget plan、phase／driver／orchestrator及必要producer接線，
   以補充決策hash約束入口和桶。原limit、spent25、歷史receipt及journal保留；
   不把新決策變成新計數器。受影響測試、一次審查及回退準備通過後才可接線。
3. 先離線逐項確認既有adapter與producer每個IO都有桶及上限；超過先STOP。
   安排本人新憑證前，仍須完成既定本地安全與還原準備。
4. 真正開始後最多一次RPC；任何前置不符就停止且不送RPC。不得靠額度仍有
   剩餘就開始另一階段。結果只回報這次入口成功、失敗或UNKNOWN。
5. 若未能在160內完整執行，停止這個試驗方法，列出具體缺失及剩餘授權；
   不再次要求同一320擴額，不回頭重跑已失敗的GAS效能樣本。

本草案不新增費用、Scope、正式資料存取或刪除，不代替本人憑證操作。
不保證一次試驗成功，也不承諾它成功後即可上線；其目的為用較少步驟取得
第一個實際可行性否決／通過結果。未批准前原兩次及原八窗規則仍有效，試驗維持STOP。
