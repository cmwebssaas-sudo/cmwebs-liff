# Phase 95.6 — Landlord LIFF Authenticated Verification

## Decision

The Phase 95.5 transport fix remains operational. After a new staging landlord
and Workspace were registered, a real mobile LIFF execution verified the
landlord identity, active Workspace membership, contracts route, billing route,
and tenant-route denial. `landlord_home` remains blocked because the new
Workspace onboarding status is not complete.

No Production resource or staging schema was modified.

## Authentication evidence

### Chrome session

The LIFF opened successfully and displayed the signed-in LINE profile name
`Hans`. The staging landlord registration page reported this identity as not
registered. This is the known staging tenant identity, not the registered
staging landlord identity.

Consequently:

- `landlord_home` could not be tested as a positive landlord request.
- `landlord_contracts_init` could not be tested as a positive landlord request.
- `landlord_billing_lifecycle_init` could not be tested as a positive landlord
  request.
- Landlord-to-tenant negative RBAC could not be tested because the session was
  not a landlord.

The system did not incorrectly elevate the tenant session into a landlord
session.

### Secondary browser session

The staging landlord page could be opened, but the LIFF runtime returned
`Failed to fetch` before a verified LINE profile was available. No UID, token,
or authenticated backend request was obtained from this environment.

### Registered landlord mobile session

After the user completed staging landlord and Workspace registration, the same
smoke URL produced authenticated landlord results:

- `landlord_contracts_init`: `OK`
- `landlord_billing_lifecycle_init`: `OK`
- cross-role `tenant_home`: denied with `TENANT_BINDING_REQUIRED`
- `landlord_home`: denied with `ONBOARDING_REQUIRED`

This proves the new LINE identity now resolves an active landlord user,
Workspace, and membership. The remaining failure is a lifecycle prerequisite,
not an authentication, transport, or RBAC identity failure.

## Route verification matrix

| Identity | Route | Expected | Result | Evidence |
| --- | --- | --- | --- | --- |
| Registered landlord | `landlord_home` | PASS | BLOCKED | `ONBOARDING_REQUIRED` |
| Registered landlord | `landlord_contracts_init` | PASS | PASS | `OK` |
| Registered landlord | `landlord_billing_lifecycle_init` | PASS | PASS | `OK` |
| Registered landlord | `tenant_home` | Denied | PASS | `TENANT_BINDING_REQUIRED` |
| Registered tenant | `landlord_home` | Denied | PASS | Phase 95.5 returned `WORKSPACE_REQUIRED` |

The mobile result proves LIFF initialization, token acquisition, bridge
transport, and server-side token verification reached the backend. It also
proves the verified identity currently resolves as a tenant. It does not prove
that the device used the same LINE UID that created the landlord fixture.

`WORKSPACE_REQUIRED` is returned after a user record is found but no active
Workspace plus membership pair can be selected. The remaining root-cause
possibilities are therefore limited to:

1. The mobile LINE account is the tenant account rather than the registered
   landlord account.
2. The intended landlord UID is present in `V2_users`, but its
   `V2_workspace_members` row is missing, inactive, or references a different
   user/workspace key.
3. The registration was completed under a different LINE UID from the one used
   by this smoke test.

This phase does not choose among these possibilities without a read-only row
comparison.

## Security interpretation

- No caller-supplied LINE UID was used.
- No token or full UID was recorded.
- A tenant session was not accepted as a landlord.
- No result has been promoted from BLOCKED or NOT TESTED to PASS without a real
  authenticated landlord execution.

## Remaining prerequisite

The registration flow creates the Workspace with onboarding status `pending`.
`landlord_home` requires completed onboarding, whereas the read-only contracts
and billing routes require only an active Workspace membership. This explains
the exact observed split without weakening authorization.

The staging hosting artifact currently contains the isolated landlord
registration page but does not contain a staging-safe landlord onboarding page.
The repository root has `landlord-onboarding.html`, but it must not be opened as
a staging workaround until its endpoint, LIFF, and navigation configuration are
isolated from Production.

## Completion procedure

1. Prepare or deploy a staging-isolated landlord onboarding flow without using
   Production endpoints or LIFF configuration.
2. Complete the required staging Workspace onboarding steps.
3. Re-open the existing landlord smoke URL.
4. Accept the Phase only when `landlord_home` also returns PASS while the other
   three already-confirmed results remain unchanged.

Do not register a new landlord or change the existing binding merely to satisfy
this verification.
