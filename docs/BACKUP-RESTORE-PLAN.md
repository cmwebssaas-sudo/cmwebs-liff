由負責人確認。

## 1. 復原目標

| 項目 | 目標 |
| --- | --- |
| 最大資料損失 | 24 小時 |
| 恢復服務時間 | 4 小時 |
| 備份驗證 | 每日自動檢查，每月人工抽查 |
| 復原演練 | 每季一次，重大架構變更前加做一次 |

目標以第一次演練的實測結果校正。

## 2. 保護範圍

| 資料 | 優先度 | 復原來源 |
| --- | --- | --- |
| 正式 Google Sheets | 最高 | 每日複本、每週異地備份 |
| 合約、證件、報修與抄表檔案 | 最高 | 檔案清單與增量備份 |
| 會員與訂閱資料庫 | 高 | 資料庫備份 |
| LINE Token 與各服務金鑰 | 高 | 負責人保管，必要時重新產生 |
| Apps Script 排程與 Web App 設定 | 中 | 手冊中的設定清單 |
| LINE、LIFF、Webhook、圖文選單 | 中 | 手冊中的設定清單 |
| 程式與網站 | 低 | Git、Apps Script 版本、GitHub Pages |
| Cloudflare D1 讀取資料 | 低 | 從 Sheets 全量同步重建 |

## 3. 備份做法

### 3.1 Google Sheets

- 每天台北時間 04:00 前完成完整複本，避開 03:00 全量同步。
- 複本放在私人資料夾，不對外分享，檔名含日期。
- 保留 14 份每日備份與 12 份月備份。
- 每週把備份加密後存到 Google 帳號以外的位置。
- 每次檢查工作表數量、欄位、列數與帳務總額。

先實測完整複製時間。逾時就改為只匯出有資料的範圍，並分批處理。

### 3.2 Google Drive 檔案

- 建立檔案清單，內容含檔案 ID、大小、更新時間與校驗值。
- 每天只備份新增或變更的檔案。
- 備份資料夾維持私人權限。
- 備份不公開、不分享，也不寫入 Git。

### 3.3 會員資料庫

- 確認現有備份的排程、保留期限、加密與異地保存。
- 缺少定期備份時，建立備份並做隔離還原。
- 資料庫備份與加密金鑰分開保存。

### 3.4 金鑰

- 金鑰由負責人保管在密碼管理器。
- Git、Sheets、聊天紀錄與手冊都不保存金鑰內容。
- 手冊只記錄名稱、用途、更換步驟與負責人。
- 無法取回的金鑰一律重新產生，不嘗試讀取舊值。

### 3.5 設定

每次變更都更新手冊的設定清單：

- Apps Script 排程與執行身分
- Web App 部署版本
- LINE 頻道、LIFF、Webhook 與圖文選單
- Cloudflare Worker、D1 與排程
- GitHub Pages

## 4. 演練前檢查

演練前逐項確認，任一項未通過就停止：

- [ ] 負責人已核准時間、範圍與複本保留方式
- [ ] 正式環境沒有進行中的部署或資料修正
- [ ] 確認複製試算表時，綁定的 Apps Script 不會連到正式資源
- [ ] 隔離環境沒有排程
- [ ] 隔離環境沒有 LINE Token，也沒有其他正式金鑰
- [ ] 隔離環境的 Spreadsheet ID 指向複本
- [ ] D1 使用隔離資料庫
- [ ] 複本放在私人資料夾，沒有對外分享
- [ ] 已決定演練後保留或刪除複本

## 5. 第一次演練

1. 記錄開始時間。
2. 建立正式 Sheets 的隔離複本。
3. 比對工作表數量、欄位與列數。
4. 比對帳單總額、付款總額與租約筆數。
5. 建立隔離 Apps Script 與 Web App，確認沒有排程及 LINE Token。
6. 用隔離資料庫完成 D1 全量同步。
7. 抽查登入、房間、帳單、合約與私人檔案權限。
8. 從備份還原一個測試檔案，核對校驗值。
9. 記錄結束時間、問題與實際耗時。
10. 依事前決定處理複本，並留下處理紀錄。

## 6. 通過條件

- 資料比對沒有未解釋的差異
- 隔離環境可完成主要讀取流程
- 整個演練期間沒有 LINE 訊息或其他對外通知
- 正式環境的資料、排程與部署都未改變
- 實測時間符合復原目標，或已列出改善項目

演練紀錄只保存數量、耗時與結果，不保存房客資料。

## 7. 中止條件

出現下列情況就立即停止：

- 發現隔離環境可連到正式資料
- 出現任何對外訊息
- 正式服務異常
- 複本權限不符合私人設定
- 複製失敗且原因不明

停止後保留紀錄，檢查影響，再由負責人決定是否重新演練。
