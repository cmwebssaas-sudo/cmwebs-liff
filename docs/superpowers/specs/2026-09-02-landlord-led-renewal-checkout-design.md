# 房東主導續約與到期退房流程設計

狀態：待使用者審閱
日期：2026-09-02
建議模型：`gpt-5.6-terra / medium`

## 目標

將租約生命週期改為房東主動、房客被動回覆：

1. 合約到期前，系統準備帶入原條件的續約草稿。
2. 房東確認租期、租金、押金、管理費、電費、設備耗損費與 30 天條款。
3. 系統通知房客選擇同意續約或不續約。
4. 同意後直接進入新版合約簽署；不續約後進入房東退房待辦。
5. 雙方私下處理時，房東可從房客詳細頁直接手動辦理退房。

## 範圍與非範圍

本次移除的是新流程中的「房客提出合約申請／房東審核申請」環節，不刪除既有
`V2_contract_requests` 歷史資料，也不破壞既有待處理申請的讀取與結案能力。
提前解約等既有申請資料先保留相容讀取；新的到期不續約不再要求房客提交
termination request。

本次不修改既有合約全文、不刪除房客主檔、帳單、付款、簽名或文件；不新增
共用 LINE OA、第三方簽章、退租費用計算或 V3 多租戶功能。

## 使用者流程

### 1. 到期前續約

到期工作程序依現有到期窗口產生一份 append-only 續約草稿，沿用原合約欄位。
房東在房東入口檢視或修改草稿，完成房東確認後，系統直接發送續約意願通知給
房客。房東確認前不得通知房客，也不得建立正式簽署邀請。

房客只看到續約內容與兩個回覆：同意續約、不續約。房客不再看到或使用提出
續約／到期退租申請的入口。

### 2. 房客同意續約

房客同意後，系統在同一個受控操作中：

- 將續約意願記為 `accepted`；
- 建立或保留新版 append-only 合約；
- 自動產生並發送新版合約簽署邀請；
- 保留舊合約與其簽名、文件、金額快照。

後續仍沿用現有房客簽署與房東核准啟用的安全邊界；新版本未簽署、未核准前，
不得封存舊版本或切換房間目前合約。

### 3. 房客不續約

房客回覆不續約後，系統不建立新合約、不發簽署邀請，並在房東端顯示
「待辦理退房」。退租日預設為原合約到期日；房東進入退房流程完成點交與帳務
確認後，才正式結案。

### 4. 私下協議的房東手動退房

房東可從「房客名單 → 房客詳細 → 房客合約」對目前或已到期合約按
「手動辦理退房」。此入口不要求房客先送申請，也不自動發送續約詢問或退租
訊息；房東自行確認私下協議內容、退房日與備註後完成操作。

手動流程要防止選到已有更新版本的舊合約；若該合約已有正式續約版本或簽署中
邀請，操作必須拒絕並要求先處理現有流程。

## 狀態與資料邊界

| 事件 | 合約狀態 | 房間狀態 | 房客／歷史資料 |
| --- | --- | --- | --- |
| 房東確認續約草稿 | 保留草稿狀態 | 不變 | 保留原資料 |
| 房客同意 | 建立／保留新版待簽 | 不切換目前合約 | 舊版唯讀 |
| 新版簽署且房東核准 | 新版 `active`，舊版 `renewed`／`archived` | 指向新版 | 全部版本保留 |
| 房客不續約 | 進入待退房，不建立新版 | 不立即釋出 | 保留帳務與合約歷史 |
| 房東完成退房 | 原合約 `terminated`，記錄退房來源與時間 | `vacant`，清除目前租約指向 | 房客主檔、帳單、付款、文件保留 |

「完成退房」是一次具權限的租約生命週期結案，不是刪除資料，也不是修改已
簽署文件內容。重複送出必須以 idempotency key 或既有結案狀態安全回傳相同結果。

## API 與頁面調整

- 修改房東確認續約草稿分支，使系統自動觸發續約意願通知；房東確認後不再需要
  另外按一次「詢問房客續約意願」。已有通知時只回傳既有結果，不重複發送。
- 修改續約意願 accepted 分支，使系統自動觸發正式新版簽署邀請；已有邀請時
  只回傳既有結果，不重複發送。
- 新增 Workspace/RBAC 保護的房東直接退房初始化／完成 route（實際 route 名稱
  依 repository 命名規則決定），支援原合約 ID、退房日、房東備註與 idempotency。
- 直接退房完成時同步更新合約生命週期欄位、房客目前合約指向與房間目前租客
  指向；所有更新必須限定同一 Workspace 與授權房東。
- 房東房客詳細頁新增「待辦理退房」與「手動辦理退房」入口；到期合約可用，
  已有新版 active 或簽署中的合約則隱藏或拒絕。
- 新流程不再把房客導向 `tenant_contract_request_submit` 的 termination；舊
  `landlord-contract-requests.html` 保留歷史／相容處理，但不再是新流程主入口。
- 新 route 同步更新 `docs/04-API-ROUTES.md`、測試矩陣與 runtime tests；不新增
  每頁獨立 API URL、LIFF ID 或測試 UID。

## 錯誤處理與安全規則

- 房東身份、Workspace、membership、room、tenant、contract 必須逐層驗證。
- 合約不存在、跨 Workspace、已完成退房、已有新版或資料不完整時 fail closed。
- 房客不續約只允許一次有效轉換；重複回覆不重複建立退房紀錄或通知。
- 房東手動退房不自動推送 LINE，避免私下協議被系統誤發通知；操作結果保存
  在通知／稽核資料中供房東查閱。
- 正式合約文件與簽名 artifact 只讀保存；不得為了退房覆寫合約全文或日期。

## 測試與驗收

新增或調整以下測試：

1. 房東確認續約後自動發送意願通知，房客不會收到房東確認前的通知；房客同意後
   只建立一份簽署邀請。
2. 房客不續約後不產生 termination request，房東可看到待退房狀態。
3. 已到期合約可由房東直接完成退房，合約結案、房間釋出、房客主檔與帳務
   歷史保留。
4. 既有 active、renewed、signing、跨 Workspace 與重複請求邊界均 fail closed
   或 idempotent。
5. 房客端不再顯示新的 termination request 提交流程；既有歷史申請仍可讀取。
6. 執行 repository validation、Apps Script syntax check、受影響 runtime/UI
   tests、全套 Node tests 與 `git diff --check`。

正式驗收另需登入後確認：506／其他已到期房客的待退房顯示、手動退房按鈕、
同意續約後簽署邀請、不續約後退房結案，以及 LINE WebView／手機版流程。
