# CMWebs 操作手冊

**狀態：** 初稿
**Issue：** [#298](https://github.com/cmwebssaas-sudo/cmwebs-liff/issues/298)
**日期：** 2026-11-02（Asia/Taipei）

公開 repository 只記錄流程。金鑰、資源 ID、主機位址、帳號與房客資料都不
寫在這裡。備份與演練規則見 `docs/BACKUP-RESTORE-PLAN.md`。

## 1. 共通規則

- 正式部署、資料修改、金鑰更換與對外訊息都要負責人同意。
- 先確認影響範圍，再處理。不確定時先停止寫入。
- 不用 `test=1` 當作不寫入的測試模式。
- 不直接大規模修改正式 Google Sheets。
- 處理紀錄不保存房客個資。

## 2. 日常檢查

### 每天

- [ ] 備份成功
- [ ] 沒有未處理的 Apps Script 失敗通知
- [ ] 登入與首頁正常

### 每月 5 日中午後

- [ ] 當月帳單通知已發送
- [ ] 沒有帳單停在發送中
- [ ] 未發送帳單都有合理原因

### 每月底

- [ ] 抽查備份內容
- [ ] 檢查 Apps Script 版本數量與儲存空間
- [ ] 檢查 Google Drive 與 Cloudflare 用量

## 3. 發布與回退

### GitHub Pages

合併到 main 就會發布。

1. 確認 PR 測試結果與範圍。
2. 合併時保留分支。
3. 確認 Pages 完成對應 commit。
4. 比對線上版本與 main。

回退方式：以 PR 還原問題提交，再確認 Pages 重新發布。

### Apps Script

1. 從 main 匯出乾淨程式碼，不在編輯器直接修改。
2. 記錄目前版本作為回退版本。
3. 建立新版本，更新既有 Web App 部署，維持網址不變。
4. 用不寫入的請求確認版本。
5. 確認排程仍然存在。

回退方式：把既有部署切回前一版。若主程式已改動，時間觸發器會使用編輯器
HEAD，也要把 HEAD 還原到相同版本。

### Cloudflare

- 部署前記錄目前 Worker 版本。
- 回退時先切回前一版，再檢查讀取是否恢復。
- D1 資料有問題時，停用快速讀取，讓頁面回到 Apps Script，再重建 D1。

## 4. 故障處理

### 4.1 Apps Script 失敗通知

1. 記錄函式、開始與結束時間、錯誤訊息。
2. 判斷是否影響帳單、付款、通知或登入。
3. 查執行紀錄，確認是否重複發生。
4. 帳單排程失敗時，檢查當月帳單的發送狀態。
5. 只有確認沒有重複風險，才補做。

### 4.2 帳單通知未發送

1. 確認排程時間已到。
2. 確認帳單符合已開立、未作廢、未繳清及未發送條件。
3. 檢查是否有卡在發送中的帳單，超過逾時限制後由系統恢復。
4. 檢查 LINE Token 與訊息額度。
5. 不手動重送，除非已確認不會重複。

### 4.3 Google 服務異常

1. 查 Google Workspace 狀態頁。
2. 暫停人工批次操作。
3. 記錄受影響時段。
4. 恢復後核對付款、帳單與通知。

### 4.4 LINE 異常

1. 查 LINE API 狀態頁。
2. 區分登入失敗、推播失敗與額度用盡。
3. 通知中心仍會保存事件，不重複推播。
4. 恢復後核對漏發項目。

### 4.5 Cloudflare 異常

1. 確認頁面已回到 Apps Script 讀取。
2. 檢查同步心跳。
3. 恢復後確認同步與讀取正常。

### 4.6 會員系統異常

1. 確認登入與租管主流程是否受影響。
2. 暫停付款確認與方案異動。
3. 恢復服務後核對付款與使用期間。

## 5. 資料復原

### 誤刪或改壞資料

1. 暫停相關寫入與排程，避免覆蓋。
2. 確認發生時間與影響範圍。
3. 找出事故前最近的備份。
4. 在隔離副本比對差異。
5. 由負責人確認要復原的範圍。
6. 只修改受影響資料，不整份覆蓋。
7. 重建 D1，並核對帳務。

### 服務需要完整復原

1. 判定主要資料是否可信。
2. 暫停排程與所有對外訊息。
3. 還原最新可信備份到新環境。
4. 確認資料比對結果。
5. 由負責人核准切換。
6. 恢復 Web App、排程與 Webhook。
7. 重建 D1。
8. 補登備份時間點之後的資料。

切換前不得恢復通知，避免房客收到錯誤訊息。

## 6. 金鑰外洩

1. 判定外洩金鑰與可能的使用範圍。
2. 立即在原服務撤銷或重新產生。
3. 更新正式環境。
4. 確認功能恢復。
5. 檢查異常使用紀錄。
6. 記錄處理過程，不記錄金鑰內容。

個資可能外洩時，暫停對外說明，先由負責人確認通報義務。

## 7. 定期工作

| 頻率 | 工作 |
| --- | --- |

## 8. 非公開設定清單

下列內容保存在負責人的私人文件，不進 Git：

- 帳號與負責人
- 正式資源 ID
- 金鑰名稱與保管位置
- 排程清單
- LINE、LIFF、Webhook 與圖文選單設定
- 異地備份位置
- 緊急聯絡方式
