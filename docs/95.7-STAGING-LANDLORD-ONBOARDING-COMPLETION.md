## Existing Backend Audit

Phase 95.7 重用既有 `V2_LANDLORD_ONBOARDING.js` business model，沒有建立第二套 onboarding 狀態或 route。

| Route | Existing handler | Purpose | RBAC permission |
|---|---|---|---|
| `landlord_onboarding_init` | `getLandlordOnboardingByLineUid_` | 讀取 workspace、membership、landlord 與 onboarding progress | `workspace_read` |
| `landlord_onboarding_save` | `saveLandlordOnboardingByLineUid_` | 依序保存 payment、property、room step | `settings_write` |
| `landlord_onboarding_complete` | `completeLandlordOnboardingByLineUid_` | 驗證必要資料與關聯後完成 onboarding | `settings_write` |

既有合法狀態轉移：

```text
pending
  -> in_progress/payment
  -> in_progress/property
  -> in_progress/room
  -> completed/completed
```

完成條件沿用既有 schema：default payment account、first property、first room。Phase 95.7 在完成前額外驗證 workspace basic profile、active membership、landlord、property 與 room 的 canonical 關聯；沒有直接手動改寫 `onboarding_status`，狀態仍由正式 handler 完成。

## Authorization and Isolation

- 所有請求使用 Phase 95.5 `staging-secure-api.js` authenticated POST transport。
- LIFF token 由 server-side verification 決定身分；frontend 不傳送 LINE UID。
- `V2_RBAC.js` policy 未修改。
- save/complete 仍要求 `settings_write`，僅 workspace owner/admin 或既有授權角色可操作。
- request 的 `workspace_id` 若與 authenticated context 不同，回傳 `WORKSPACE_ACCESS_DENIED`。
- membership、landlord、property 或 room 任一 workspace 關聯不一致即 fail closed。
- 缺少必要資料回傳 `ONBOARDING_INCOMPLETE` 或更精確的 relation/profile code，不會完成 onboarding。
- 重複 complete 在已完成狀態下回傳 `ALREADY_COMPLETED`，且不再寫入 Sheet，具 idempotency。

### Real LIFF timeout diagnosis and correction

The first real landlord LIFF attempt reached the correct onboarding page but showed `API 載入逾時`. The staging Apps Script execution record provides the authoritative timing:

- route execution: version 18 `doPost`
- started: 2026-07-23 04:07:52 Asia/Taipei
- duration: 30.679 seconds
- Apps Script status: completed
- frontend timeout: 30 seconds

The request therefore completed after the browser had already closed the bridge. The read-only `landlord_onboarding_init` path called `onboardingEnsureSchema_()`, which called `workspaceEnsureSchema_()`, and then called `getLandlordWorkspaceContextByLineUid_()`, which ran `workspaceEnsureSchema_()` a second time. The init request was performing two schema migration passes before normal reads.

Version 19 applies the minimal staging-only correction:

- `landlord_onboarding_init` no longer runs `onboardingEnsureSchema_()`.
- It calls the existing workspace context function with `skipSchemaEnsure: true`.
- Existing callers retain the original schema-ensure default.
- save and complete routes retain their schema checks and business behavior.
- The frontend timeout remains 30 seconds; it was not increased to conceal backend latency.
- RBAC, API schema, LIFF configuration and Production remain unchanged.

Deployment identifiers and credentials are intentionally not recorded in this report.
