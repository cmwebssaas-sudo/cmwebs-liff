## 2. LINE identity verification reliability

The server continues to ignore caller-provided UID and accepts only the
verified LINE ID-token `sub` claim.

Reliability behavior:

- only POST authentication is accepted;
- HTTP 429, HTTP 5xx and provider exceptions are retried within a bounded
  1–3 attempt policy;
- elapsed request time is checked against a configurable 1–10 second
  application deadline;
- invalid, expired or wrong-audience tokens fail without retry;
- exhausted provider failures are recorded in
  `V2_SECURITY_FAILURE_QUEUE` only when its feature is enabled;
- failure records contain action, error class, attempt count and provider
  status only—never ID token, LINE UID or access token;
- tokens are deliberately not queued for asynchronous replay.

Apps Script does not expose a hard network-socket timeout option for
`UrlFetchApp.fetch`. The application deadline therefore rejects an over-budget
response after the call returns; it cannot interrupt a stalled platform call.

## 3. RBAC and Workspace isolation

- All 71 `landlord_*` routes remain explicitly mapped.
- Unmapped landlord routes fail with `RBAC_POLICY_MISSING`.
- Viewer, maintenance, manager and financial permission-negative fixtures pass.
- A caller-supplied `workspace_id` must match the Workspace resolved from the
  authenticated membership; mismatch fails with `WORKSPACE_ACCESS_DENIED`.
- Dispatcher authorization receives the request parameter boundary explicitly.

## 4. Settlement ledger migration and rollback protection

New admin-only functions:

- `migrateSettlementLedgerSchema()`
- `validateSettlementLedgerSchema()`
- `migrateStagingSecurityHardening()`
- `validateSecurityHardeningReadiness()`

Migration is additive and gated by both:

- `CMWEBS_FEATURE_SCHEMA_MIGRATIONS`
- `CMWEBS_FEATURE_MOVE_OUT_SETTLEMENT`

Validation confirms:

- all 16 ledger headers;
- no duplicate Workspace/operation/idempotency key;
- only supported transaction statuses;
- rollback protection readiness.

Runtime operations cannot create or extend the ledger. Missing or invalid
schema fails closed. Tests cover committed replay and a forced mid-operation
failure that restores settlement, request and repair rows and records
`rolled_back`.

## 5. Notification stale-processing recovery

Before normal queue selection, the worker now scans `processing` jobs whose
lease is older than `CMWEBS_NOTIFICATION_PROCESSING_TIMEOUT_MINUTES`.

- retry count below 3: clear the expired lease, transition to `retrying`, and
  make the job eligible for the current worker pass;
- retry count reaching 3: transition to terminal `failed`;
- record `NOTIFICATION_PROCESSING_TIMEOUT` without tokens or message secrets;
- report recovered and failed stale-job counts in worker output.

Tests cover both automatic recovery to `sent` and terminal failure without a
fourth provider call.

   finance permission and cross-Workspace denial.

   without duplicate LINE delivery.

   the real Sheet/LockService runtime.
8. Production release SHA manifest, immutable rollback version and named human
   approval are still required.

2. Set every required staging property; never copy Production secrets.
3. Enable schema migration temporarily.
4. Run `migrateStagingSecurityHardening()` once.
5. Disable schema migration immediately.

   result.

8. Generate an exact Production release SHA manifest.
9. Configure Production properties with all features disabled.
10. Promote features one at a time only after human approval and retain the
