## Authenticated bridge blocker

A read-only POST probe confirmed that the staging Apps Script backend returns HTTP 200 and generates the expected structured `LINE_ID_TOKEN_INVALID` envelope for an intentionally invalid token. The response is wrapped by the Apps Script HtmlService sandbox.

The current backend bridge output at `release/staging/apps-script/V2_API.js` uses `window.parent.postMessage(...)`. In the HtmlService response, user HTML executes inside a nested sandbox iframe, so `window.parent` is the Apps Script wrapper rather than the tenant/landlord page. The frontend listener therefore never receives the envelope and times out. The frontend also requires `event.source === frame.contentWindow`, which cannot match a message originating from the nested HtmlService sandbox.

This is a response-transport defect, not a missing LIFF login, missing token, RBAC policy failure, or hosting synchronization failure.

RBAC was not marked PASS based only on static tests.

## Remaining blocker and minimal next action

The release remains blocked until a staging-only bridge change safely delivers the HtmlService response to the top-level LIFF page. The minimal follow-up should:

1. Change the staging backend bridge target from the nested parent to the top-level window.
2. Update frontend message validation for the Apps Script sandbox origin while retaining the random request ID and fixed envelope source checks.
3. Add negative tests for forged origin, forged request ID, and forged envelope source.
4. Deploy a new immutable staging Apps Script version only, then rerun tenant and landlord authenticated API and RBAC tests.

No production change is authorized by this report.

## Decision

**NO-GO**

Hosting synchronization and artifact integrity are complete, but real authenticated tenant and landlord API calls remain blocked by the HtmlService nested-frame response path. Production remains untouched.
