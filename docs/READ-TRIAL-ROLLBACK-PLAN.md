## Fixed lifecycle receipt prerequisite

The fixed orchestrator now requires an immutable path/manifest pin and original
canonical recovery options. Construction stays pure. In the original preparation
scope, import the verified copied runtime, compare its recovery epoch to the
current canonical view and construct its cleanup control against the existing
claim/checkpoint. The permanent epoch registry binds that counter and options;
this creates no second scope and makes no holder-liveness claim.

Check again after preparation/before handoff, before each compatibility entry,
and at the final outbound transport seam after asynchronous release/native/sign
work. A stop during recovery checks must not begin preparation afterwards.
Source or counter readiness failures retain the original lifecycle's independent
cleanup and native settlement. Failure after R admission leaves a charged
UNKNOWN/pending attempt even when no transport was sent; never refund or replay.

Ruling: readiness is a local protocol/source prerequisite, not Google rollback
acceptance. If actual native callbacks are missing, the trial is still blocked
by its original gates. A damaged snapshot cannot revoke already-held in-memory
cleanup authority; actual source/counter damage may nevertheless prevent cleanup
and must remain unresolved rather than being repaired or hidden.

The canonical driver accepts a paired readiness hook for this trusted fixed
lifecycle: awaited prepareDispatch runs after R admission but before native/time/
token checks and request minting; synchronous assertDispatch runs before the
last native/time/token/signature checks and transport. A Promise returned by the
synchronous assertion is denied. The fixed lifecycle always installs both; raw
canonical drivers without hooks remain local regression tools, not actual trial
authorization. The final assertion checks lifecycle stop, any original stop
marker (negative veto only), current artifact and same counter compatibility.
No awaited work remains after final synchronous guards and before invocation.

## Original holder token denial probe

The trusted lifecycle may map its existing verify-token-revoked callback to
flow.verifyRevoked(); it takes no replacement control or token argument. After
original revoke settles, the original accepted token is held in memory until
one admitted fixed userinfo GET settles. Independent I17 admission precedes
HTTP; remaining token lifetime is checked after admission and response disposal.
No credential refresh/new Scope/alias, query token, retry or durable raw token.

A401 only records original-token rejection at readback. Preserve the original
ACK_UNVERIFIED/UNKNOWN revoke result; revocationAccepted and rollbackComplete
remain false. An expired token, damaged receipt, unexpected response or denied
admission cannot be called verified revocation. A restarted holder has no raw
token to reconstruct: leave verification unavailable, retain unknown state and
continue the remaining independent cleanup. This is not a native grant-removal
or whole-rollback proof. Eight native/guard callbacks remain incomplete.
